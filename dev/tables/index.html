Tables

Loading a tabulated EOS, checking it, and generating an analytic one.

Table repair is not part of this package: it is an offline activity performed once before a simulation campaign, and the run-time path contains no repair logic. check_table is what detects a table that has not been repaired.

EntropyEOS.T_HI_ROWS_DROPPED_ATTR — Constant

Name of the attribute – in a file, of the scalar dataset read_stellarcollapse surfaces as it – that records how many of the source table's hottest T rows the C++ repair has already dropped (RepairOptions::trim_t_hi_rows, 1.2.0). A table without it has dropped none.

EntropyEOS.check_table — Method
check_table(t, opts = CheckOptions()) -> CheckReport

Audit a RawTable and report what is wrong with it. Never throws: structural problems that would make the later checks unsafe are caught and reported as fatal_messages with status = Status.fatal, and the non-structural classes are then skipped.

  • A. Structural (fatal). Axes strictly increasing and finite; required fields logenergy/entropy and attribute energy_shift present; those two fields finite everywhere.
  • B. Range/positivity. entropy_negative, plus a nonfinite_<field> class for each non-interpreted field that carries a non-finite value.
  • C. Monotonicity in T. entropy_nonmonotone_T, logenergy_nonmonotone_T.
  • D. Maxwell consistency. delta_T, delta_p, maxwell_s_rho; needs logpress and at least 3 ρ and T points, otherwise a single skipped maxwell_consistency placeholder.
  • E. Sound speed. cs2_out_of_range and, when D's inputs are also available, the report-only cs2_vs_fd; only when a cs2 field exists.

EntropyEOS.SeamDefect — Type

Plant a ρ-column stitching seam, mimicking the Hempel DD2/SFHo seam at ρ ≈ 1.4e7 g/cm³ (C++ 1.2.0).

Above log10(T/MeV) = logT_onset, every node at iρ ≥ iρ_a + 2 is shifted by step(T) and the node at iρ_a + 1 by step(T)/2, where

step(T) = amplitude · ((logT - logT_onset) / (logT_max - logT_onset))²

and logT_max is the grid's own top: a level step across cells iρ_a … iρ_a+2 that grows smoothly from zero with T and is the same at every Yₑ. It goes in as step to "logpress", step/2 to "logenergy" and as the factor 10^step to "entropy", so all three carry the matching kink, as on the real tables. Because the shift only grows with T, monotonicity in T is untouched; what it breaks is smoothness in ρ.

EntropyEOS.apply_stiffen! — Method

Step 4: add amplitude·(ρ/ρ_c)^α erg/g to the physical energy, everywhere.

The field is stored as a log10, so the term is added to 10^value and the result re-logged – identical to adding it to ε, since energy_shift is a constant. There is no cutoff: for α > 0 the term falls off as ρ^-α and drops below the last bit of ε + energy_shift on its own, which is what keeps the defect analytic in ρ and exactly independent of T and Yₑ.

EntropyEOS.make_synthetic_table — Function
make_synthetic_table(opts = SyntheticOptions()) -> RawTable{Float64}

Sample the analytic model on the grid described by opts and apply its defects.

Stored fields are "logenergy" = log10(ε + energy_shift), "entropy" = s and "logpress" = log10(p), plus the "energy_shift" attribute. With opts.with_aux_fields three more follow – "cs2", "gamma" (5/3 flat) and "mu_e" – which the check/repair pipeline never interprets, so a defect planted in one of them can only ever be reported as non-finite, never as fatal.

With opts.with_composition, the datasets a CompositionTable reads follow: mu_e, muhat, munu, Xn, Xp, Xa, Xh, Xl, Abar, Zbar (replacing the auxiliary mu_e). They are not physics. Each is multilinear in (a, b, c), the table's (log₁₀ρ, log₁₀T, Yₑ) mapped onto [0, 1], so that trilinear interpolation reproduces them exactly anywhere in the box:

mu_e  = 5 + 20a + 3b + 40c + 2abc     (MeV)
muhat = 2 + 30a − b + 10c             (MeV; munu = mu_e − muhat)
Xn = 0.1 + 0.2a,  Xp = 0.1 + 0.1b,  Xa = 0.1 + 0.1c,  Xl = 0.05ab
Xh = 1 − Xn − Xp − Xa − Xl            (between 0.2 and 0.7)
Abar = 50 + 10a + 20c + 5ab,  Zbar = 20 + 5b + 8c

Defects are applied to the stored representation, after every field is in place, in the fixed order flatten, wiggle, offset, stiffen, seam, seed, setvalue, each list running to completion before the next begins.

Cold β-equilibrium

Initial data for a cold neutron star: the states of least Gibbs energy at each pressure among those with μ_ν = 0 on the table's coldest row, with the phase transitions between them explicit.

EntropyEOS.BetaEquilibrium — Type
BetaEquilibrium{T}

One state of a ColdBetaSlice, as beta_equilibrium returns it.

  • ρ★, yₑ, s: the state. s = srange(eos, ρ★, yₑ).s_min, the coldest tabulated temperature.
  • point: the EOS evaluated there, giving p, U, h, cs², ….
  • g: the Gibbs free energy per unit rest mass, 1 + U − T̂s + p/ρ★ + c_E·Yₑ with c_E the slice's energy_offset in these units. As T → 0 it is point.h corrected for the rest masses the table's energy leaves out. It, not point.h, is continuous across a phase transition and non-decreasing along the slice, and dg = dp/ρ★ there.
  • flags: point.flags, plus FLAG_CLAMP_YE if β-equilibrium lies outside the table's Yₑ range and yₑ is that range's edge.
source
EntropyEOS.ColdBetaJump — Type
ColdBetaJump

A phase transition on a ColdBetaSlice: at pressure p the density jumps from ρ★_lo to ρ★_hi and the composition from yₑ_lo to yₑ_hi. No equilibrium state has a density strictly in between.

g is the Gibbs free energy there. g_mismatch is its jump, high side minus low side: zero (to rounding) where two branches' g cross. It is nonzero only where no crossing exists: a branch that appears at p with g already below the current one's (seen once, on SRO LS220, at −1.2·10⁻⁷), or a branch that ends at p still below the next. The slice's g is held at the low side's value across a negative mismatch, so that it stays non-decreasing.

source
EntropyEOS.ColdBetaSlice — Type
ColdBetaSlice

The cold, neutrinoless β-equilibrium states of a tabulated EOS, built by cold_beta_slice and queried with beta_equilibrium.

Its vertices are stored in order of increasing density, and along them ρ★, p and g are non-decreasing; at a phase transition two vertices share p and g.

  • ρ★, yₑ, s, p, h, g, clamped: the vertices' states (h is the EOS's enthalpy, g the Gibbs free energy of BetaEquilibrium);
  • jumps: the phase transitions, in order of increasing pressure;
  • munu_offset: the constant c in μ_ν = mu_e − muhat + c, in MeV;
  • energy_offset: the correction c_E in E = m_B ε + c_E·Yₑ, in MeV per baryon: the energy whose Yₑ-derivative is μ_ν;
  • munu_mismatch: the fraction of the coldest row's nodes where the table's own munu differs from mu_e − muhat + c by more than 1 keV.
source
EntropyEOS.beta_equilibrium — Method
beta_equilibrium(slice::ColdBetaSlice; ρ★ | p | g) -> BetaEquilibrium

The cold β-equilibrium state at a given rescaled density ρ★, pressure p (in EOSPoint units) or Gibbs free energy g; pass exactly one.

A TOV solve wants p or g: each gives one state, also across a phase transition, where the state is the low-density phase below the jump and the high-density phase at and above it. A density inside a jump's gap has no equilibrium state and throws ArgumentError, as does a value outside the slice. Between vertices the state is solved for on the branch the vertices lie on, so μ_ν = 0 there too.

source
EntropyEOS.cold_beta_slice — Method
cold_beta_slice(table::RawTable, eos::EOSTable; refine = 8,
                munu_offset = nothing, energy_offset = nothing) -> ColdBetaSlice

The cold, neutrinoless β-equilibrium slice of eos, which must have been built from table.

Criterion. μ_ν = mu_e − muhat + munu_offset = 0 on the table's coldest row, interpolated bilinearly in log10 ρ and Yₑ. munu_offset is 0 if the table's muhat includes the neutron–proton mass difference Q, −Q if not; by default it is read off the table's free nucleons in their ideal-gas limit, as for CompositionTable, and is 0 on all four real tables. Where the table's own munu disagrees, as O'Connor–Ott LS220's does above about 10⁸ g/cm³ by a further −Q, the disagreement is reported in munu_mismatch and not followed.

Selection. At refine densities per table cell, every upward zero crossing of μ_ν in Yₑ, and a table edge where μ_ν points outward, is placed on the fitted EOS's cold edge. Neighbouring samples' crossings that are each other's nearest in Yₑ form branches, which are cut where the pressure stops rising. At each pressure the branch with the least Gibbs free energy g is the equilibrium; where that changes, g is equal on both branches at one pressure, located by bisection on exact states, and the density jumps there.

Energy correction. The tables' ε leaves out rest masses that μ_ν includes, so g uses E = m_B ε + energy_offset·Yₑ. By default energy_offset = munu_offset + mₑc², since the tables' mu_e includes the electron's rest mass and their ε does not. That is checked: above 10¹³·⁵ g/cm³, (mu_e − muhat) − m_B ∂ε/∂Yₑ must be mₑc² to within 20 keV. A table that fails, as O'Connor–Ott LS220 does, throws ArgumentError unless energy_offset is given explicitly.

"Cold" means the table's lowest temperature, not T = 0. The table must carry mu_e and muhat, and, unless munu_offset is given, Xn and Xp with an ideal-gas region or else munu.

Composition

The chemical potentials, mass fractions and mean heavy nucleus of a table, for neutrino rates, evaluated in a kernel. Build a CompositionTable from the raw table and the EOS built from it, once; then call composition next to evaluate, at the temperature the recovery landed on:

ct = CompositionTable(table, eos)
matches(ct, eos) || error("composition and EOS are from different tables")
cv = CompositionView(ct)              # adapt(CuArray, cv) for a device
pt = evaluate(v, ρ★, s, yₑ, NaN)
c = composition(cv, ρ★, pt.T_MeV, yₑ)
η_ν = c.μ_ν / pt.T_MeV
η̂_nucleons = (c.μ̂ - q_np(cv)) / pt.T_MeV   # without rest masses
EntropyEOS.Composition — Type
Composition{T}

The composition at one state, from composition. isbits.

  • μ_e, μ̂, μ_ν in MeV. μ_e includes the electron's rest mass. μ̂ includes the neutron–proton mass difference Q (q_np) on every table, so that μ_ν = μ_e − μ̂ exactly. The nucleons' own degeneracy, without rest masses, is (μ̂ − Q)/T.
  • X_n, X_p, X_α, X_h, X_l: mass fractions of free neutrons, free protons, α particles, heavy nuclei, and the light clusters other than α (0 on a table without them), each in [0, 1]. They are not renormalized.
  • Ā, Z̄: mass and charge number of the mean heavy nucleus. Where there are no heavy nuclei, X_h = 0, Ā = 1 and Z̄ = 0.

CompositionView

Kernel-side view of a CompositionTable: the nine interpolated fields, interleaved as c[field, iρ, jT, kYₑ] so that one lookup's corners are contiguous, plus the grid and the scalars. Adapt.adapt moves it to a device and narrow narrows it, as for an EOSTableView.

EntropyEOS.composition — Method
composition(cv, ρ★, T_MeV, yₑ) -> Composition

The composition at rescaled density ρ★, temperature T_MeV and electron fraction yₑ. T_MeV is the temperature the recovery landed on, EOSPoint.T_MeV, not T̂.

Trilinear in (log₁₀ρ, log₁₀T, Yₑ) on the raw table's grid, with log₁₀ρ = log₁₀(ρ★/κ); each coordinate is clamped to the table's axes, and there is no extension. The result carries no flags: EOSPoint.flags already marks a state outside the box. Ā and Z̄ are X_h-weighted means over the cell's corners, so that the tables' fill values where there are no heavy nuclei never enter: X_h·Ā and X_h·Z̄ are the trilinear interpolants of those products.

Allocation-free and exception-free; runs in a device kernel.

EntropyEOS.CompositionTable — Method
CompositionTable(raw::RawTable, eos::EOSTable; munu_offset = nothing) -> CompositionTable

The composition of the table raw, for evaluation with composition in a kernel next to eos, which must have been built from the same file (fingerprint); otherwise this throws ArgumentError. Opt-in: a code that does not need the composition carries none of its arrays (nine fields per node, 180 MB in Float64 on DD2).

Reads mu_e, muhat, Xn, Xp, Xa, Xh, Abar, Zbar, and those of Xd, Xt, X3he, X4li and Xl the table has; every one must be finite.

munu_offset is the constant c in μ_ν = mu_e − muhat + c: 0 if the table's muhat includes Q (q_np), −Q if it does not. By default it is read off the table's free nucleons in their ideal-gas limit, as cold_beta_slice does; a table without that limit falls back to its munu, read only then. Either must give 0 or −Q, or the build throws; pass it explicitly for a table with another convention. Stored μ̂ is muhat − munu_offset, so that it includes Q on every table. All four real tables' muhat already does.

Mass fractions are clamped to [0, 1] at the nodes, and Ā, Z̄ to ≥ 0; where Xh = 0 they are stored as 1 and 0.

EntropyEOS.muhat_offset — Method
muhat_offset(table::RawTable, who; munu_offset = nothing) -> Float64

The constant c in μ_ν = mu_e − muhat + c, in MeV: 0 if the table's muhat includes the neutron–proton mass difference Q, −Q if it does not. who prefixes the error messages.

Where the free nucleons are a hot, dilute ideal gas (T 2–10 MeV, log10 ρ ≤ 10, Xn and Xp above 0.05), a muhat that includes Q is Q + T ln[(Xn/Xp)(m_p/m_n)^{3/2}]. The median of muhat minus that, over those nodes, must be 0 or −Q to within 0.1 MeV, and is rounded to it; otherwise this throws. The test reads only the table's own composition, not munu, whose convention can differ from its muhat's (O'Connor–Ott LS220's, above 10⁸ g/cm³). A table without such nodes, or whose residuals spread by more than 0.05 MeV (the synthetic tables, which are not physics), falls back to the median of munu − (mu_e − muhat) on the coldest row, which must then be 0 or −Q to within 10 keV.
